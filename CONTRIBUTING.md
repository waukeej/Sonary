# Contributing

1. Fork the repository and create a separate branch.
2. Keep each change focused on a single task and reuse shared components.
3. In the pull request, describe what changed and which checks were performed.
4. Do not commit `.env`, credentials, user uploads, database dumps, cookies, or local paths.
5. Use a separate test database and disposable data for local checks.

Do not include third-party music or other materials without permission. Report vulnerabilities according to `SECURITY.md`. The project's licensing terms have not yet been determined.
